Changelog

Version 1.4.0 · 2026-09-30

This edition makes 16 reader-facing changes: 13 additions, 1 deprecation, 1 correction, 1 clarification. No guidance was removed.

Compared with Version 1.3.1.

  1. Correction · Front matter

    Evidence review advanced to September 30

    The handbook now identifies September 30, 2026 as its latest evidence review.

    This edition incorporates primary documentation, advisories, and research published after the prior review date.

    Sources: OpenAI: API changelog

  2. Addition · 3. Context engineering, not long prompts

    Compaction is a state transition

    Section 3 now treats provider-managed compaction as an explicit state transition. It requires exact preservation of signed summaries, compatible instructions and tools, durable storage for evidence that compaction can remove, separate usage accounting, and a successful continuation before state advances.

    Managed compaction can silently omit details, replace prior messages, remove uploaded evidence, and bill summarization outside the top-level request totals.

    Sources: Anthropic: Compaction on demand

  3. Addition · 10. Structured outputs: syntax is only the first gate

    Structured outputs need fault containment

    Section 10 now caps grammar and schema work, isolates it from shared inference, and requires malformed structured-output requests to fail inside the originating request.

    An unhandled constraint error can terminate a shared serving engine and turn one invalid request into a multi-tenant availability failure.

    Sources: vLLM Project: Structured-output request errors can terminate a shared EngineCore

  4. Addition · 11. Reliable function and tool calling

    Late tool results are reauthorized

    Section 11 now reauthorizes every late result against the current tenant, principal, conversation, run, call, resource, and state version, and discards results for work that is no longer active.

    A delayed callback can otherwise revive an obsolete plan, spend outside its original budget, or attach to a reused call identifier.

    Sources: Google: Gemini API release notes · OpenAI: Computer use

  5. Addition · 11. Reliable function and tool calling

    Dynamic tools become versioned runtime state

    Section 11 now requires a server-owned, authorized tool registry, a canonical schema digest on every turn, and rejection when a call targets a different tool version.

    Adding or removing tools during a conversation changes the execution contract and can make replay, authorization, and revocation ambiguous.

    Sources: Anthropic: Mid-conversation system messages

  6. Addition · 11. Reliable function and tool calling

    Plausible tool results need semantic verification

    Section 11 now verifies consequential tool results against authoritative state and tests fluent, internally consistent falsehoods alongside malformed responses and exceptions.

    A valid schema says nothing about whether an entity, value, unit, provenance record, or timestamp is actually correct.

    Sources: Original research authors: Agents' Overreliance on Unreliable Tools

  7. Deprecation · 13. Model routing and degraded mode

    Managed agent surfaces join the deprecation matrix

    Section 13 now tracks managed agent runtimes, built-in tools, approval and sign-in behavior, retained state, and retirement dates alongside model and API versions.

    A managed surface can retire or change its tool contract independently of the underlying model family.

    Sources: Google: Gemini API release notes · Google: Gemini API deprecations

  8. Clarification · 13. Model routing and degraded mode

    Preserved reasoning state is route-scoped

    Section 13 now parses model responses by block type, binds signed reasoning state to the exact provider, model, account, history, and API contract, and requires an explicit compatible checkpoint when a route cannot preserve it.

    Current migrations can change default reasoning, tool-choice rules, structured-output parameters, refusal handling, and the meaning of an effort level.

    Sources: Anthropic: Developer platform release notes · Anthropic: Migrating to Claude Sonnet 5.5

  9. Addition · 16. Evals as the release contract

    Black-box judges need local stability checks

    Section 16 now calibrates judges on the exact endpoint, version, rubric, language, and release window, repeats representative judgments, and records disagreement and rank stability.

    Shared judge endpoints can change enough across repeats or days to invalidate a calibration borrowed from another endpoint or time window.

    Sources: Original research authors: A Stability Audit of Shared Black-Box LLM Judge Endpoints

  10. Addition · 16. Evals as the release contract

    Multimodal injection is measured by carrier and stage

    Section 16 now tests visible text, metadata, audio, video, files, screenshots, and retrieved media, and separates noticing, planning, tool calls, and completed external effects.

    A low completed-attack rate can still conceal a much higher rate of attempted unsafe action.

    Sources: Original research authors: MMPIBench: Multimodal Prompt Injection Benchmark

  11. Addition · 19. Safety engineering and permission boundaries

    API keys are governed as production identities

    Section 19 now requires an owner, purpose, environment, service scope, maximum lifetime, rotation path, last-used visibility, and revocation drill for every production API key.

    Provider-enforced expiry and lifetime policy make credential age a control the system can prove, not a spreadsheet field.

    Sources: OpenAI: API changelog

  12. Addition · 19. Safety engineering and permission boundaries

    Agent skills join the software supply chain

    Section 19 now pins and reviews agent skills, instruction bundles, transitive files, and scripts, limits their privileges, and retests them after updates.

    Reusable skills can carry persistent behavior that activates after installation or in a different run.

    Sources: Original research authors: SkillShift: Supply-Chain Risks in Agent Skills

  13. Addition · 20. Multi-tenant isolation and cache safety

    Resource limits move to the earliest acquisition point

    Section 20 now caps fields before hashing or metrics, bounds compressed and remote media before full materialization, rechecks limits after transformation, and contains per-request failures inside the request.

    Recent serving vulnerabilities repeatedly bypassed limits through an earlier input path or a later processor-specific transformation.
